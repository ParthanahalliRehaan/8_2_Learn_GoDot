# How to design/Architect scenes?
## Your example is correct

You could have:

```text
res://
├── scenes/
│   ├── player.tscn
│   ├── enemy.tscn
│   ├── sword.tscn
│   ├── tree.tscn
│   └── village.tscn
```

Each scene contains the nodes needed for that thing.

For example:

```text
Player.tscn
└── CharacterBody2D
    ├── Sprite2D
    ├── CollisionShape2D
    └── Camera2D
```

And:

```text
Enemy.tscn
└── CharacterBody2D
    ├── Sprite2D
    ├── CollisionShape2D
    └── ...
```

Then you can create a larger scene:

```text
Level1.tscn
├── Player
├── Enemy
├── Enemy
├── Enemy
├── Tree
├── House
└── ...
```

The important part is that **Player.tscn itself can be placed inside Level1.tscn**. This is called **instancing a scene**.

So instead of rebuilding:

```text
CharacterBody2D
├── Sprite2D
├── CollisionShape2D
└── Camera2D
```

every time you need a player, you make `Player.tscn` once and reuse it.

## Think of scenes as reusable blueprints

```text
Player.tscn
     ↓
   Player
     ↓
 ┌───┼────┐
 ↓   ↓    ↓
P1   P2   P3
```

One `Player.tscn` can produce multiple instances of the player.

And the same idea applies to:

```text
Enemy.tscn
    ↓
Enemy 1
Enemy 2
Enemy 3
Enemy 4
```

So your mental model is now:

> **A scene is a collection of nodes organized into a hierarchy, saved as a reusable `.tscn` file. We can make separate scenes for different game objects, characters, environments, UI elements, or even larger game systems.**

That last part matters. **Scene ≠ model.** A scene can represent anything that benefits from having its own structure and reusable behavior.

## 4. A scene can contain another scene

**Correct, with an important term: *instancing*.**

Suppose you have:

```text
Player.tscn
└── Player
    ├── Sprite2D
    └── CollisionShape2D
```

Then in:

```text
Level1.tscn
└── World
    ├── Player
    ├── Enemy
    └── Tree
```

that `Player` can be an **instance of `Player.tscn`**.

Conceptually:

```text
Player.tscn
     ↓
  instance
     ↓
Level1.tscn
```

This is one of the reasons scenes are so powerful. You build the player once and reuse it.
