# Day 1 Tasks: Identify fileSystem dock,scene dock, Inspector And Output debugger.
# 1. What is a file system, inspector in goDot?
Your project is going to become a collection of **scenes, nodes, assets, and properties**. Godot's editor is basically the control room for all of that. Humans apparently needed a graphical interface to arrange files and objects instead of just suffering through text.

Your Dawn 1 instructions explicitly identify the **FileSystem dock, Scene dock, Inspector, and Output/Debugger** as the important parts of the editor layout. 

## 1. FileSystem: "What exists in my project?"

Look at the **bottom-left** of your screenshot.

You currently have:

```text
res://
└── icon.svg
```

This is Godot showing you your project's files.

Think of it like your **project's filesystem explorer**.

### `res://` means

`res://` represents the **root directory of your Godot project**.

So later, your project might look conceptually like:

```text
res://
├── assets/
│   ├── art/
│   ├── audio/
│   └── fonts/
├── scenes/
│   ├── main_menu.tscn
│   ├── continent_1.tscn
│   └── player.tscn
├── src/
│   ├── player/
│   └── enemies/
└── project.godot
```

Your development document actually proposes this kind of separation between assets, source code, scenes, and documentation. 

### What goes into FileSystem?

Things such as:

* `.tscn` → scenes
* `.gd` → GDScript files
* `.png` → images
* `.svg` → vector assets
* `.ogg` / `.wav` → audio
* `.tres` → Godot resources
* fonts
* shaders
* other project assets

So when you create something in Godot, you're usually dealing with **two different concepts**:

> **The thing exists as a file**
> **The thing is currently being edited/used in a scene**

That distinction will become very important.

# 2. Scene dock: "What objects exist right now?"

Look at the **top-left** of your screenshot.

Right now it says:

```text
Scene
Import
```

and underneath:

```text
Create Root Node:

2D Scene
3D Scene
User Interface
Other Node
```

You haven't created a scene yet, which is why Godot is asking you what the root node should be.

Once you create one, you'll get something more like:

```text
Main
└── Player
    ├── Sprite
    └── CollisionShape
```

This is called the **Scene Tree** or **Node Tree**.

This is one of the most important concepts in Godot:

> **Everything in a scene is organized as nodes in a parent-child hierarchy.**

For example:

```text
Player
├── Sprite2D
└── CollisionShape2D
```

means:

* `Player` is the parent.
* `Sprite2D` belongs to the Player.
* `CollisionShape2D` belongs to the Player.

The parent-child relationship isn't merely organizational. Properties such as transforms and lifecycle behavior can flow through that hierarchy. Your Dawn 1 material specifically calls this out. 

This is the part I want you to understand deeply rather than memorizing buttons.

# 3. Inspector: "What are the properties of this thing?"

Now look at the **right side**.

That's the **Inspector**.

At the moment it's basically empty because **you haven't selected a node**.

Once you select something, the Inspector changes.

For example, imagine you have:

```text
Player
```

and click it.

The Inspector might show things conceptually like:

```text
Player
────────────────
Transform
    Position
    Rotation
    Scale

Visibility
    Visible
    Modulate

Physics
    Collision Layer
    Collision Mask

Script
    ...
```

The Inspector is therefore **not your filesystem** and it's not your scene tree.

It answers:

> **"What configuration does the currently selected object have?"**

Your Dawn 1 material summarizes it as **"Inspector → Edit node properties."**

# 4. The relationship between the three

This is the mental model I want you to keep:

```text
              GODOT PROJECT
                    │
          ┌─────────┴─────────┐
          │                   │
      FileSystem           Scene
      "What exists?"       "What's here?"
          │                   │
          │             ┌─────┴─────┐
          │             │           │
          │           Player      Enemy
          │             │
          │        ┌────┴────┐

          │
          └──────────────┐
                         │
                    Inspector
                  "How is the
                   selected
                   thing
                   configured?"
```

That's much more useful than memorizing where the buttons are.

# 5. Example from our actual game

Suppose we're eventually building the player.

The **FileSystem** might contain:

```text
res://
├── scenes/
│   └── player.tscn
├── src/
│   └── player/
│       └── Player.gd
└── assets/
    └── art/
        └── characters/
            └── player.png
```

Then `player.tscn` might contain:

```text
Player
├── AnimatedSprite2D
├── CollisionShape2D
└── Camera2D
```

And if you select:

```text
Player
```

the Inspector lets you configure the Player.

If you select:

```text
CollisionShape2D
```

the Inspector now shows properties belonging to **that node**.

If you select:

```text
AnimatedSprite2D
```

the Inspector shows properties belonging to **that node**.

So:

> **Scene Tree = hierarchy**
> **Inspector = configuration**
> **FileSystem = project resources/files**

That's the core distinction.

# 6. One subtle but extremely important distinction

Suppose you have:

```text
res://player.tscn
```

That is a **file**.

When you open it, Godot displays the nodes contained inside that scene:

```text
Player
├── Sprite
└── CollisionShape
```

So:

**FileSystem**

```text
player.tscn
```

↓

**opens**

```text
Player scene
```

↓

**Scene Tree**

```text
Player
├── Sprite
└── CollisionShape
```

↓

**select a node**

```text
Sprite
```

↓

**Inspector**

```text
Sprite properties
```

That chain is worth understanding now because later you'll be creating reusable scenes everywhere. Your development plan explicitly describes a `.tscn` as a reusable component that can be saved and instanced elsewhere.

# Your Dawn 1 learning target

Don't try to learn every Godot panel today.

For now, you should be able to look at the editor and mentally say:

| Panel          | Question it answers                            |
| -------------- | ---------------------------------------------- |
| **FileSystem** | "What files/resources exist in my project?"    |
| **Scene Tree** | "What nodes make up this scene?"               |
| **Inspector**  | "How is the selected node configured?"         |
| **Viewport**   | "What does my scene look like spatially?"      |
| **Output**     | "What is the engine telling me while it runs?" |

And there's one more concept sitting underneath all of this:

**Node → Scene → Project**

```text
Node
 ↓
combine nodes
 ↓
Scene (.tscn)
 ↓
combine scenes/assets/scripts
 ↓
Game project
```

That hierarchy is the foundation we're going to build on. **Don't touch movement, physics, cameras, animation, or GDScript yet.** If the Scene/Node/FileSystem/Inspector relationship isn't clear, those later topics become cargo cult programming very quickly.
