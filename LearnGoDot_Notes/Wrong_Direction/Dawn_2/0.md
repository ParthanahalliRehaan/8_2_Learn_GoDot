# Step 2: Find Viewport Width

Inside Project Settings, there should be a **Filter Settings** search box.

Type:

```text
viewport width
```

You should find something similar to:

```text
Display
└── Window
    └── Size
        └── Viewport Width
```

Set it to:

```text

```

Godot 4.7's actual setting is:

`display/window/size/viewport_width`

and this defines the base viewport width used by the stretch system. ([Godot Engine documentation][1])

# Step 3: Set Viewport Height

Search:

```text
viewport height
```

Set:

```text
360
```

So we now have:

```text
Viewport Width  = 640
Viewport Height = 360
```

### Why?

Your game's internal canvas becomes:

```text
┌──────────────────────────────────┐
│                                  │
│          640 × 360               │
│                                  │
└──────────────────────────────────┘
```

That's the resolution at which we're designing the pixel-art world.

The 640×360 choice is also exactly one of the resolutions specified in your Dawn 2 instructions.

# Step 4: Set Stretch Mode

Now search:

```text
stretch mode
```

Find:

```text
Display
└── Window
    └── Stretch
        └── Mode
```

You should have choices including:

```text
Disabled
Canvas Items
Viewport
```

Set:

**Viewport**

### What does this actually mean?

This is important.

With Viewport mode:

```text
Your game
   ↓
640 × 360
   ↓
Godot renders it
   ↓
scales that finished image
   ↓
actual monitor
```

So the pixel-art image is created at the low resolution **first**.

Godot 4.7 explicitly describes `viewport` this way and recommends it for games using a pixel-art aesthetic. ([Godot Engine documentation][1])

---

# Step 5: Set Stretch Scale Mode

Search:

```text
scale mode
```

Find:

```text
Display
└── Window
    └── Stretch
        └── Scale Mode
```

Set:

**Integer**

Not Fractional.

This is one of the most important settings for your game.

---

## What Integer actually does

Suppose the player's monitor is:

```text
1920 × 1080
```

Your base game is:

```text
640 × 360
```

Godot can calculate:

```text
1920 / 640 = 3
1080 / 360 = 3
```

So:

```text
640 × 360
      ↓ ×3
1920 × 1080
```

Every game pixel becomes a consistent block.

### Fractional scaling could do something ugly(Texture filtering)

Imagine:

```text
640 × 360
      ↓ ×2.37
```

Now one game pixel doesn't necessarily correspond to the same number of physical screen pixels.

That's where pixel-art rendering starts becoming unpleasant.

Godot's 4.7 documentation says Integer scaling floors the final scale factor so the screen remains an integer multiple of the base viewport. ([Godot Engine documentation][1])

---

# Step 6: Set Stretch Aspect

This one is easy to overlook.

Search:

```text
stretch aspect
```

Set:

**Keep**

You want:

```text
640 × 360
```

to preserve its 16:9 aspect ratio.

For example:

```text
640 × 360
16:9
```

should not become:

```text
700 × 360
```

because that would stretch everything horizontally.

Godot's `keep` aspect mode preserves the base aspect ratio and can add letterboxing/pillarboxing when necessary. ([Godot Engine documentation][1])

# Why we're using Viewport instead of the `canvas_items` in your instructions

Your `instructions.md` says:

```text
Stretch Mode: canvas_items
Scale: integer
```



But you're using **Godot 4.7.1**, and its current documentation says:

* `canvas_items` renders directly at the target resolution.
* `viewport` renders at the base viewport first, then scales that viewport.
* `viewport` is recommended for pixel-art aesthetics. ([Godot Engine documentation][1])

So I'm deliberately teaching you the **version-correct configuration**, rather than making you blindly obey an old setting.

This is exactly the sort of thing you should learn as an engineer: **requirements are not the same thing as implementation details**.

# Part 2: Texture filtering

Now we're going to make sure your actual pixel art doesn't get blurred.

Search Project Settings for:

```text
default texture filter
```

You should find something under:

```text
Rendering
└── Textures
    └── Canvas Textures
        └── Default Texture Filter
```

Set it to:

**Nearest**

Godot's `Nearest` filter reads the nearest pixel rather than blending surrounding pixels. ([Godot Engine documentation][2])

---

## Why Nearest matters

Imagine your sprite has:

```text
BLACK BLACK WHITE WHITE
BLACK BLACK WHITE WHITE
WHITE WHITE BLACK BLACK
WHITE WHITE BLACK BLACK
```

Nearest filtering preserves those hard boundaries.

Linear filtering can calculate intermediate values between pixels.

Instead of:

```text
██░░
██░░
░░██
░░██
```

you can end up visually closer to:

```text
▓▒░
▒▓▒
░▒▓
```

Which is useful for normal photographic textures.

Not what we want for pixel art.

Your Dawn 2 instructions explicitly require **Nearest** for the test sprite.

# Part 3: Pixel snapping

Now search Project Settings for:

```text
snap 2d transforms
```

You should find:

```text
Rendering
└── 2D
    └── Snap
        └── Snap 2D Transforms to Pixel
```

Enable:

**On**

Godot 4.7 describes this as snapping CanvasItem positions to full pixels, which is useful for low-resolution pixel-art games. ([Godot Engine documentation][1])

### Why?

Suppose your character is at:

```text
Position:
X = 100
Y = 50
```

Nice.

But if movement produces:

```text
X = 100.37
Y = 50.82
```

the object is now sitting between pixel coordinates.

Pixel snapping effectively makes the rendered position behave like:

```text
X = 100
Y = 51
```

This can make pixel art considerably crisper.

### Important

Godot has both:

```text
Snap 2D Transforms to Pixel
Snap 2D Vertices to Pixel
```

For now, use **Transforms**.

Godot's documentation specifically warns against enabling both simultaneously because movement can become less smooth. ([Godot Engine documentation][1])

# Part 8: Add Sprite2D

At the top-left of the Scene dock, click the **+** button.

Search:

```text
Sprite2D
```

Select:

**Sprite2D**

Create it.

Your scene tree should now be:

```text
Dawn2Test
└── Sprite2D
```

This introduces an important Godot concept:

### `Node2D`

A `Node2D` is a node with a 2D transform:

```text
Position
Rotation
Scale
```

### `Sprite2D`

A `Sprite2D` is a 2D visual node that displays a texture.

So architecturally:

```text
Dawn2Test
    │
    └── Sprite2D
          │
          └── test_sprite.png
```

The node provides the **behavior/transform**.

The PNG provides the **visual data**.

That separation becomes very important later when your player, enemies, items, and world objects all become reusable scenes.

# Part 10: Center it

Because the Sprite2D is a child of the Node2D, its position is initially near:

```text
0, 0
```

For a test, set its position approximately to:

```text
X = 320
Y = 180
```

Why?

Because:

```text
Viewport = 640 × 360
```

and:

```text
640 / 2 = 320
360 / 2 = 180
```

So:

```text
(320, 180)
```

is the center of your game viewport.

This is your first tiny lesson in coordinate systems.

```text
(0,0)
  ┌─────────────────────────────┐
  │                             │
  │                             │
  │            (320,180)        │
  │                ●            │
  │                             │
  │                             │
  └─────────────────────────────┘
                         (640,360)
```

Godot's 2D coordinate system starts at the top-left.

# Your first debugging exercise

Don't just tell yourself:

> "It looks okay."

We want to verify the pipeline.

You should understand this chain:

```text
LibreSprite
     │
     │ PNG
     ▼
Godot Importer
     │
     │ Nearest
     ▼
Sprite2D
     │
     │ 32×32 texture
     ▼
640×360 Viewport
     │
     │ Integer scaling
     ▼
Monitor
```

If the final image is blurry, we ask:

```text
Where did the pixels become blurry?
```

Possible causes:

```text
Wrong viewport
      ↓
Wrong stretch mode
      ↓
Fractional scaling
      ↓
Linear filtering
      ↓
Sprite-specific filtering
      ↓
Subpixel positioning
```

That is debugging.

Changing random settings until the problem disappears is not debugging. It is ritual sacrifice with a GUI.
