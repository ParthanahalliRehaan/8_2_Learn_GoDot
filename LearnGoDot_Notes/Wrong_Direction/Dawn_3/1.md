# 4. Understand `extends Resource`

Start with:

```gdscript
class_name PlayerStats
extends Resource
```

Two completely different concepts are happening here.

## `extends`

```gdscript
extends Resource
```

means:

> `PlayerStats` is a type of `Resource`.

Godot has an inheritance system.

Think:

```text
Resource
   ↑
PlayerStats
```

`PlayerStats` gets the functionality provided by `Resource`.

A `Resource` is particularly useful for **data objects**.

Examples later:

```text
PlayerStats
ItemData
LoreEntry
WeaponData
EnemyData
```

Your project's architecture explicitly uses `Resource` for data containers, and the Dawn 3 instructions introduce it alongside `class_name` and `@export`. 

---

# 5. Understand `class_name`

```gdscript
class_name PlayerStats
```

This registers your script as a globally usable type.

Without it, the script is basically:

```text
some_script.gd
```

With it:

```text
PlayerStats
```

becomes a recognized type.

Later you can write:

```gdscript
var stats: PlayerStats
```

instead of treating it as some anonymous script.

This is one reason **static typing** becomes useful.

# 6. Your first variables

Now add:

```gdscript
@export var max_health: int = 100
@export var speed: float = 200.0
@export var player_name: String = "Wanderer"
```

Let's dissect one:

```gdscript
@export var max_health: int = 100
```

There are four pieces.

### `@export`

```gdscript
@export
```

tells Godot:

> Expose this variable in the Inspector.

So eventually you'll be able to select something using this resource and see:

```text
Max Health: 100
Speed: 200.0
Player Name: Wanderer
```

This is editor integration, not ordinary GDScript syntax.

---

### `var`

```gdscript
var
```

means:

> Create a variable.

A variable is simply named storage for a value.

```text
max_health → 100
speed      → 200.0
```

---

### `: int`

```gdscript
max_health: int
```

means:

> `max_health` must be an integer.

Examples:

```gdscript
100
50
0
-20
```

Not:

```gdscript
100.5
```

---

### `= 100`

```gdscript
= 100
```

sets the initial value.

So:

```gdscript
var max_health: int = 100
```

means:

> Create an integer called `max_health` and initialize it to `100`.

---

# 7. The important difference: `int` vs `float`

Compare:

```gdscript
var health: int = 100
```

and:

```gdscript
var speed: float = 200.0
```

`int`:

```text
100
25
0
-10
```

`float`:

```text
100.0
25.5
0.25
-10.75
```

For health, an integer is sensible.

For movement speed, decimals are useful:

```text
200.0 pixels/sec
150.5 pixels/sec
```

The Dawn 3 source specifically introduces `int`, `float`, `String`, `bool`, `Vector2`, `Array`, and `Dictionary` as the built-in types you'll encounter.

# 9. Now the interesting variable

Add:

```gdscript
var current_health: int:
	set(value):
		current_health = clampi(value, 0, max_health)
```

This looks considerably more annoying than:

```gdscript
var current_health: int = 100
```

That's intentional.

We're introducing a **property setter**.

---

# 10. What is a setter?

Suppose someone does:

```gdscript
stats.current_health = 500
```

We don't necessarily want that.

If:

```gdscript
max_health = 100
```

then having:

```text
current_health = 500
```

would make no sense.

So we intercept the assignment.

```gdscript
set(value):
```

means:

> Whenever somebody tries to assign a new value to `current_health`, run this code.

For example:

```gdscript
current_health = 70
```

causes the setter to receive:

```text
value = 70
```

Then:

```gdscript
clampi(value, 0, max_health)
```

restricts it.

---

# 11. What does `clampi()` do?

This:

```gdscript
clampi(value, 0, max_health)
```

means:

```text
minimum = 0
maximum = max_health
```

If:

```text
value = 70
max_health = 100
```

result:

```text
70
```

If:

```text
value = 150
```

result:

```text
100
```

If:

```text
value = -20
```

result:

```text
0
```

So:

```text
        0 -------------------- 100
        ↑                       ↑
      minimum                maximum
```

Health is now protected by an invariant:

```text
0 <= current_health <= max_health
```

That's the important engineering concept.

We're not merely "setting health."

We're enforcing a **valid state**.

---

# 12. Add `_init()`

Now:

```gdscript
func _init() -> void:
	current_health = max_health
```

This is a function.

Specifically, `_init()` is the initialization function.

When the `PlayerStats` object is created, we want:

```text
max_health = 100
current_health = 100
```

rather than:

```text
max_health = 100
current_health = 0
```

---

# 13. Understand `-> void`

Look at:

```gdscript
func _init() -> void:
```

The structure is:

```text
func
 ↓
_init()
      ↓
      -> void
```

`-> void` means:

> This function does not return a value.

Compare:

```gdscript
func reset_health() -> void:
	current_health = max_health
```

versus:

```gdscript
func is_alive() -> bool:
	return current_health > 0
```

The first returns nothing.

The second returns a Boolean.

Your Dawn 3 material explicitly calls out using `->` for return types. 

---

# 14. Add `is_alive()`

Finally:

```gdscript
func is_alive() -> bool:
	return current_health > 0
```

This function asks:

> Is the player currently alive?

If:

```text
current_health = 100
```

then:

```gdscript
100 > 0
```

is:

```text
true
```

If:

```text
current_health = 0
```

then:

```gdscript
0 > 0
```

is:

```text
false
```

So:

```gdscript
is_alive()
```

returns:

```text
true / false
```

That's why its return type is:

```gdscript
-> bool
```

# 15. Your complete Dawn 3 script

Your file should now look like this:

```gdscript
class_name PlayerStats
extends Resource

@export var max_health: int = 100
@export var speed: float = 200.0
@export var player_name: String = "Wanderer"

var current_health: int:
	set(value):
		current_health = clampi(value, 0, max_health)

func _init() -> void:
	current_health = max_health

func is_alive() -> bool:
	return current_health > 0
```

This is the exact structure provided by the Dawn 3 instructions.

# 19. Now test the setter

Change `_ready()` to:

```gdscript
func _ready() -> void:
	stats = PlayerStats.new()

	print("Initial health: ", stats.current_health)

	stats.current_health = 50
	print("After damage: ", stats.current_health)

	stats.current_health = 200
	print("After invalid increase: ", stats.current_health)

	stats.current_health = -50
	print("After invalid decrease: ", stats.current_health)

	print("Alive: ", stats.is_alive())
```

Expected:

```text
Initial health: 100
After damage: 50
After invalid increase: 100
After invalid decrease: 0
Alive: false
```

This is the actual lesson.

You didn't just create a variable.

You created a variable with a **state invariant**.

```text
current_health
      │
      ▼
   setter
      │
      ▼
   clampi()
      │
      ▼
  valid state
```
