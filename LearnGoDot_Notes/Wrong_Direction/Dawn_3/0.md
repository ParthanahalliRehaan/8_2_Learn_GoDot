# Doubts
**D1**:*Why do we seperate these src scenes(player.tscn) from scenes/main.tscn?, How do we connect them? Do we use signals*
**D2**:*Why do we write extends resource, Also we create a scene then attach a script then a object can use this script. What is this object?*
**D3**:*When you run a scene, first child nodes scene is runned?*
**D4**:*Does Init() doesnt need a function to call?*
- `_init()` in GDScript is the constructor — it runs automatically when you create a new instance with `.new()`. You don’t need to call it manually; it’s triggered behind the scenes during object creation.
# Answers
1. **D1:** We separate `src/player/Player.tscn` from `scenes/Main.tscn` to keep **reusable game components** separate from **game composition**.
2. `Player.tscn` defines what a Player *is*; `Main.tscn` defines where the Player *exists*.
3. We connect them by **instantiating Player.tscn as a child of Main**, not primarily through signals.
4. **Signals** are instead used for communication/events, such as `Player.died → Main.game_over()`.
5. *(Dont think much will understand in upcoming dawns)* **D2:** `extends Resource` means our `PlayerStats` class is a **Resource-based data container**, rather than a scene/node. 
6. A **scene** is a saved tree of Nodes; when you attach a script, that script defines the behavior of the Node it is attached to.
7. The **object** is the actual runtime instance created from that scene/class, e.g. an instantiated `Player` in memory.
8. So: `Player.tscn` = blueprint, instantiated Player Node = actual object, `Player.gd` = its behavior.
9. **D3:** When a scene runs, Godot starts with that scene's **root Node**, then its children become part of that running scene tree.
10. The key mental model: **Scene = blueprint/tree → Nodes = objects → Scripts = behavior → Signals = communication.**
# Better Answer for **D3**
Because **Godot enters the scene tree recursively**, but the exact output order depends on **where your `print()` calls are**.

If your tree is:

```text
Main
├── Player
└── UI
```

and both `Main.gd` and `Player.gd` have:

```gdscript
func _ready():
    print("...")
```

Godot calls `_ready()` on the **children first**, then their parent:

```text
1. Player._ready()
       ↓
2. UI._ready()
       ↓
3. Main._ready()
```

So you might see:

```text
Player ready
Main ready
```

This is intentional: when `Main._ready()` runs, its children have already been initialized and are ready to be used.

### Mental model

```text
Scene enters tree
      ↓
Children initialize
      ↓
Children become READY
      ↓
Parent becomes READY
```
